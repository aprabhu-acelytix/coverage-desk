# Three-minute walkthrough

**Before starting:** confirm `scripts/backend.ps1 status` reports readiness, and open Coverage Desk → Home. The validation example uses public Patagonia coverage; it is not a claim that Patagonia is a client. Reuse retained results to conserve the persistent validation budget.

**0:00–0:35 — Set the question.** Select a saved coverage search, or use New coverage search → Save & collect. Show the short form and More options. Explain that broad client queries run alongside optional campaign queries. Show the stage/count panel and readable Collection details. Reuse retained results to avoid unnecessary requests.

**0:35–1:15 — Inspect evidence.** Filter by Instagram or LinkedIn, then open View finding. Switch between Overview, Evidence and Source details. Point out the provider-returned excerpt and exact AI quotes where present. Explain that quote matching validates fidelity, not semantic correctness. Show that uncertain/irrelevant matches remain available through reversible filters.

**1:15–1:55 — Invite perspective.** Save a selected finding, explicitly choose Shared with this workspace, and decide whether to include the AI assessment/message wording. On Team board, open View finding → Discussion → Add perspective. Show the rendered Slack profile name and review status. A real second teammate can do this on a shared item; if only one person is present, say so rather than impersonating a teammate.

**1:55–2:40 — Prepare the briefing.** Open the retained draft labeled AI-assisted (managed sign-in and live analysis have passed). A separate Source-linked draft demonstrates preparation without AI. Edit its copy. Show the source links, exact AI evidence when present, and separately appended team notes.

**2:40–3:00 — Review the boundary.** Open Preview & publish and verify the exact destination/content. The configured owner must press Publish; contributor mentions can notify them. Until then nothing is posted. Explain that collaborators can edit shared artifacts but cannot invoke the owner's Codex session, and that this local backend must stay running.

Visual checks: native light/dark modes, narrow window, long headline wrapping, five-row pagination, filters, modal scroll, and owner/non-owner action availability. Check actual second-user permissions before calling the demo a real multi-user validation.
